# S3 / Cloudflare R2 — Direct Image Upload Using Presigned URLs

## 1. Important concepts

### Presigned URL

- A temporary URL generated by the backend using the storage provider's SDK.
- Grants permission to perform a specific operation, such as uploading an object.
- Has an expiry time (e.g. 60 seconds).
- Anyone possessing the URL can use its granted permission until it expires.
- It does not make the bucket or object public.

### Bucket

A bucket is a container used to store objects (files).

### Object Key

A unique path/name used to identify an object inside a bucket.

Example:
`uploads/1794570444309-a1b2c3.png`

- `uploads/` → logical folder/prefix
- timestamp + UUID → unique filename
- `.png` → file extension

S3 does not have traditional folders; prefixes in object keys create a folder-like structure.

### Public URL

A URL used to retrieve an object without generating a new presigned GET URL, provided public access is configured.

For a particular bucket and delivery configuration, the URL prefix can remain the same. The object key changes for each uploaded file.

### Private vs Public Bucket

**Private bucket**

- Objects cannot be accessed anonymously.
- Uploads can still be performed using presigned PUT URLs.
- Downloads can use presigned GET URLs or an authenticated backend.

**Public bucket**

- Objects can be read anonymously if the access policy permits it.
- Anyone with the public object URL may view the object.
- Do not use public access for sensitive files.

Important: A presigned URL does not require a public bucket.

## 2. Overall architecture — Presigned URL upload

1. User selects an image in React.
2. React sends the filename and MIME type to Express.
3. Express validates the request.
4. Express generates a unique object key.
5. Express creates a PutObjectCommand.
6. Express generates a presigned PUT URL.
7. Express returns `signedUrl` and `key` to React.
8. React uploads the actual image directly to S3/R2 using PUT.
9. Storage provider saves the image.
10. React can preview the local image.
11. Backend/database can store the object key for future retrieval.

**Important:** The image bytes do not pass through Express in this architecture.

## 3. Backend implementation

### Step 1 — Setup

Packages:

- express → API server
- cors → allows cross-origin frontend requests
- crypto → generates unique identifiers
- @aws-sdk/client-s3 → S3 commands and client
- @aws-sdk/s3-request-presigner → generates presigned URLs
- morgan → logs HTTP requests

### Step 2 — Configure Express and CORS

```ts
const app = express();

app.use(express.json());

app.use(
  cors({
    origin: "http://localhost:3000",
    methods: ["GET", "POST"],
    allowedHeaders: ["Content-Type"],
  }),
);

app.use(morgan("dev"));
```

CORS allows the browser frontend at port 3000 to communicate with the backend at port 8000.

Do not add duplicate manual CORS headers when using the `cors` middleware.

### Step 3 — Read environment variables

```env
AWS_ACCESS_KEY_ID=...
AWS_SECRET_ACCESS_KEY=...
AWS_REGION=ap-southeast-2
AWS_BUCKET_NAME=...
PORT=8000
```

These credentials must stay on the backend.

### Step 4 — Create S3 client

```ts
const s3Client = new S3Client({
  region: AWS_REGION,
  credentials: {
    accessKeyId: AWS_ACCESS_KEY_ID,
    secretAccessKey: AWS_SECRET_ACCESS_KEY,
  },
});
```

The S3Client is responsible for communicating with AWS S3.

For Cloudflare R2, configure the R2 account endpoint and credentials instead:

```ts
const s3Client = new S3Client({
  region: "auto",
  endpoint: R2_ENDPOINT,
  credentials: {
    accessKeyId: R2_ACCESS_KEY_ID,
    secretAccessKey: R2_ACCESS_SECRET_KEY,
  },
  requestChecksumCalculation: "WHEN_REQUIRED",
  responseChecksumValidation: "WHEN_REQUIRED",
});
```

### Step 5 — Generate a unique object key

```ts
const key = `uploads/${Date.now()}-${crypto.randomUUID()}.${extension}`;
```

Why?

- Avoids filename collisions.
- Prevents users from overwriting files just because they have the same filename.
- Keeps uploaded objects organized under `uploads/`.

### Step 6 — Create the POST /presign route

The frontend sends:

```json
{
  "fileName": "profile.png",
  "fileType": "image/png"
}
```

Backend validates the input:

```ts
if (typeof fileName !== "string" || typeof fileType !== "string") {
  return res.status(400).json({
    error: "fileName and fileType are required",
  });
}

if (!fileType.startsWith("image/")) {
  return res.status(400).json({
    error: "Only image uploads allowed",
  });
}
```

### Step 7 — Create PutObjectCommand

```ts
const command = new PutObjectCommand({
  Bucket: AWS_BUCKET_NAME,
  Key: key,
  ContentType: fileType,
});
```

Meaning:

- Bucket → where the file will be stored.
- Key → the unique object path.
- ContentType → MIME type of the uploaded file.

### Step 8 — Generate presigned URL

```ts
const signedUrl = await getSignedUrl(s3Client, command, {
  expiresIn: 60,
});
```

This generates a temporary URL authorizing the specified PUT operation.

### Step 9 — Return response

```ts
res.json({
  signedUrl,
  key,
});
```

Why return both?

- `signedUrl` → frontend uses it to upload the image.
- `key` → identifies the stored object and can be saved in the database.

## 4. Frontend implementation

### Step 1 — Select an image

```tsx
const [selectedFile, setSelectedFile] = useState<File | null>(null);
```

The browser provides a File object containing:

- name
- size
- type
- lastModified
- actual file data

### Step 2 — Request a presigned URL

```ts
const presignResponse = await fetch(`${BACKEND_URL}/presign`, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    fileName: selectedFile.name,
    fileType: selectedFile.type,
  }),
});
```

Notice: We send only file metadata, not the actual image.

### Step 3 — Receive signed URL and key

```ts
const { signedUrl, key } = await presignResponse.json();
```

### Step 4 — Upload directly to S3/R2

```ts
const uploadResponse = await fetch(signedUrl, {
  method: "PUT",
  headers: {
    "Content-Type": selectedFile.type,
  },
  body: selectedFile,
});
```

Important:

- Method must be PUT because the presigned command is PutObjectCommand.
- Content-Type must match the type used when signing the command.
- Body contains the actual File object.

### Step 5 — Preview the image

```ts
onUploadSuccess(URL.createObjectURL(selectedFile));
```

`URL.createObjectURL()` creates a temporary browser-local URL for previewing the selected file.

It is NOT the S3/R2 URL.

### Step 6 — Save the object key

After successful upload, send the `key` to your backend and save it in your database along with the user's record.

For example:

```json
{
  "imageKey": "uploads/1794570444309-a1b2c3.png"
}
```

Later, use the key to generate a presigned GET URL or construct the configured public delivery URL.

## 5. S3 vs R2

| Feature         | AWS S3                      | Cloudflare R2               |
| --------------- | --------------------------- | --------------------------- |
| SDK             | AWS SDK v3                  | AWS-compatible SDK          |
| Region          | AWS region                  | Usually `auto`              |
| Endpoint        | AWS-managed                 | R2 account endpoint         |
| Credentials     | AWS credentials             | R2 access credentials       |
| Presigned URLs  | Supported                   | Supported                   |
| Public delivery | Bucket/object access or CDN | Public bucket/custom domain |
| Storage API     | S3 API                      | S3-compatible API           |

The core upload flow is almost identical because R2 supports the S3-compatible API.

## 6. Common mistakes

1. Using `Bun.env` inside browser React code — Bun is not available in the browser.
2. Using restricted browser ports such as 6000 — Chrome can block them.
3. Forgetting bucket CORS configuration — browser PUT requests to storage can fail.
4. Using a different Content-Type from the one used when signing.
5. Assuming a successful PUT means the object is publicly accessible.
6. Saving the temporary presigned URL instead of the object key.
7. Exposing AWS credentials in frontend code.
8. Assuming `URL.createObjectURL()` is a permanent cloud URL.

## Final mental model

**Backend = Permission + Validation**

**Frontend = Actual file upload**

**S3/R2 = File storage**

**Database = Stores the object's key and related metadata**

**Presigned URL = Temporary permission to perform an operation**
